# Audio Replacement Mod Loading

MGSHDFix supports loading replacement audio for MG1 and MG2 without modifying the original `.sdt` files.

Audio replacements for MGS2/MGS3's `.sdt` are not supported at the moment. (Poke Afevis on our Discord if you have a project that requires MGS2/MGS3 support and I'll wire them up for ya; they're pretty much finished, I just felt lazy about testing them 100% & will happily let someone else try em out if there's a demand for it. :3)

<br />

## Supported Audio

- `.FLAC` (up to 16-bit), 16-bit PCM `.WAV`, `.OGG` and `.MP3`.
- Mono or stereo files, at 44.1 or 48 kHz. Mono will play through both left & right channels automatically; 44.1 kHz files will also be up-sampled to 48 kHz.
- Separate `.track0` and `.track1` replacements for multi-track `.sdt` files (ie MG2's Alert 3 song, which contains both level 3 & level 2 evasion variants of the song.)


<br />

## Setup

1. Enable **Modloading Support → Load Loose Audio Files** in the Config Tool.
2. Place the replacement beside the original `.sdt`. Match the `.sdt`'s filename, with `.track0` or `.track1` before the audio extension:

   ```text
   us/bgm_2/mg2_bgm04_main01.sdt
   us/bgm_2/mg2_bgm04_main01.track0.flac
   ```

3. Restart the game after adding or changing replacements or settings.


<br />


Replacements can also be placed in ASI Loader's overload folder.

If you have multiple audio files for a single track in the same folder, load order priority is **FLAC → WAV → OGG → MP3**.


<br />

Without a JSON file (see our modding development guide below), replacement tracks use the original `.sdt` file's duration and loops. Longer audio is trimmed from the end; shorter audio is padded with silence.



<br />

## ReplayGain and Volume Normalization

The Master Collection's vanilla audio files were pre-recorded EXTREMELY LOUDLY. 

MGSHDFix can automatically make replacement audio files louder (or quieter) to match the MC's vanilla audio levels with the use of ReplayGain tags applied to your replacement audio files.

- This allows you to make quiet files louder without having to amplify their volume in audacity / other audio editing software.
- These tags should typically be generated by the author of whatever audio mod you're using. Mod development info is below.
- ReplayGain tags are supported by FLAC, OGG, and in MP3 ID3 tags. 

<br />


Choose **Modloading Support → Replacement Audio Normalization**:

- **Use File Volume:** plays the file without adjusting its volume.
- **Match Game Volume:** raises the volume toward the ReplayGain target, stopping before peaks would clip. The result may be quieter than the game's audio, but peaks are not compressed.
- **ReplayGain + Limiter:** uses the exact ReplayGain gain as the base volume adjustment, then limits peaks that would clip. This stays closer to the game's volume, but compresses loud peaks.

<br />

- `REPLAYGAIN_TRACK_GAIN`: the playback volume adjustment in decibels, such as `+6.00 dB` or `-3.00 dB`.
- `REPLAYGAIN_TRACK_PEAK`: the recording's measured peak before that adjustment. This is a linear value, not decibels; `1.0` represents digital full scale. It helps determine how much gain can be applied before peaks would clip.


Files without a track gain tag will be played at their original volume regardless of selected normalization setting.

## Custom Looping Music

You can define custom looping points for your replacement music via a `.json` file with the same track name placed beside your file. This applies to music that already loops in the game.

```text
mg2_bgm04_main01.track0.flac
mg2_bgm04_main01.track0.json
```

Basic loop settings:

```json
{
  "loop_start": 576000,
  "loop_end": 4320000
}
```

Loop positions are stored in **sample frames** (ie a 44.1kHz .mp3/.flac/.wav = 44,100 samples/second, 48 kHz = 48,000 samples/second.)

```text
12 seconds × 48,000 = 576,000 frames
90 seconds × 48,000 = 4,320,000 frames
```

Use whole numbers without commas in the JSON, starting from zero. 

`loop_start` = the start of the loop (audio before this timestamp will be considered a one-time intro that only plays when the song first starts); `loop_end` is the first frame after the loop and is not played.

Each track supports a separate JSON file. Loop points must be a timestamp within the file (add a moment of silence at the end of your loop if you need it.)

<br />

## (Optional) Metadata JSON

MGSHDFix supports more comprehensive metadata json files which include the recording's sample rate, the first non-silent frame (for future seamless playback/silence trimming), and length for file validation:

```json
{
  "schema": 1,
  "sample_rate": 48000,
  "source_frames": 4800000,
  "start_frame": 0,
  "one_shot": false,
  "loop_start": 576000,
  "loop_end": 4320000
}
```

This example describes a 100-second recording at 48 kHz: 100 × 48,000 = 4,800,000 sample frames. (`sample_rate` and `source_frames` must match the audio file's actual sample rate and total frame count. Use the exact frame count from the recording, not a rounded duration displayed by a music player.)


<br />


- `schema`: json version number. We'll always try to ensure backwards compatibility with old json versions.
- `start_frame`: the first frame without silence. (Not currently utilized, silence trimming is still WIP.)
- `one_shot`: set to `true` for non-looping audio and omit `loop_start` and `loop_end`. The game's original duration and stopping behavior still apply.
- `peak`, `peak_dbfs` and `loudness_lufs`: optional measurements for reference. These fields do not currently adjust playback volume. (I may expand this support in the future once we have MGS2/MGS3's replacements set up)

Invalid JSON or metadata that does not match the recording is ignored with a warning. The replacement then uses the original track's duration and loops.


<br />

## Debug / Development Logging

Under **Internal Settings → Debugging → Loose Audio Debug Logging**:

- **Disabled:** no load diagnostics (default).
- **Trims and Padding:** logs when audio clips that are longer than the original file are trimmed, or if the clip is shorter, padded with silence.
- **Full Logging:** logs custom loops, matched lengths, and startup file indexing.
